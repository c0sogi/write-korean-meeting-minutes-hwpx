# 검증 시나리오

스킬을 수정한 뒤 다음 사례를 확인한다.

## 사례 1. 정상적인 meetdown Markdown

입력: `assets/synthetic-transcript.md`

기대 결과:

- 같은 녹음을 다시 전사하지 않음
- `Created at`을 회의 일시로 사용하지 않음
- 한 화자가 제안하고 다른 화자가 명시적으로 동의한 범위만 결정으로 분류
- 회의 날짜를 모르면 “이번 주 금요일”을 임의의 절대 날짜로 바꾸지 않음
- 제목과 절 제목은 굵게, 핵심 결정과 후속 조치는 파란색으로 표시

## 사례 2. 음성만 있고 인증정보가 있음

- `scripts/transcribe.py`를 실행
- 생성 Markdown을 `scripts/inspect_transcript.py`로 검사
- API 키를 명령과 산출물에 기록하지 않음

## 사례 3. 음성만 있고 인증정보가 없음

- 업로드 전에 중단
- 필요한 환경변수 이름을 구체적으로 안내
- 전사와 회의 내용을 만들어내지 않음

## 사례 4. 메타데이터와 참고 화면이 부족함

- 작업을 중단하지 않고 검토본 생성
- 없는 메타데이터는 `확인 필요`로 표시
- “이쪽에 넣어”만으로 특정 기관의 배치를 확정하지 않음
- 검토 항목과 음성인식 위험을 기록

## 사례 5. HWPX 왕복 검사

- `assets/example-minutes.json` 검증 통과
- 같은 템플릿에 반복 렌더링해도 스타일이 중복 누적되지 않음
- HWPX 검증 통과
- `mimetype`가 첫 항목이며 무압축 상태 유지
- 제목 교체 후에도 용지 여백(`hp:secPr/hp:pagePr`)과 단 설정(`hp:ctrl/hp:colPr`)이 보존됨
- 기본 템플릿의 한글 글자 단위·영문 단어 단위 줄 나눔이 생성 문서에도 유지됨
- 반복 렌더링 및 다른 여백을 가진 호환 템플릿에서도 설정을 임의로 덮어쓰지 않음

## 기본 명령

uv run scripts/self_test.py
